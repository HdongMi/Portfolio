PROJECT 01

주문 시스템 MSA 전환

트래픽 증가로 한계에 다다른 모놀리식 커머스 백엔드를 이벤트 기반 12개 서비스로 분리했습니다.

프로젝트 개요

기간2023.03 – 2024.06
팀 구성백엔드 6 · 인프라 2
역할테크 리드
기여도40%

사용 기술

KotlinSpring BootKafkaMySQLRedisAWS EKSTerraform

주요 기능 및 담당 역할

  • 도메인 경계 설정(주문·결제·재고·배송)과 서비스 분리 로드맵 수립
  • Transactional Outbox 패턴으로 주문 이벤트 발행의 정합성 보장
  • Strangler Fig 방식의 무중단 점진 이관 및 트래픽 섀도잉 검증
  • 서비스별 SLO 정의, 분산 추적(OpenTelemetry) 도입

문제 해결 경험

ISSUE 1주문–재고 간 데이터 불일치
문제서비스 분리 후 DB 커밋과 Kafka 발행이 분리되어, 장애 시 재고가 차감되지 않은 주문이 하루 수십 건 발생
시도2PC는 성능 부담이 커서 제외하고, Outbox 테이블 + Debezium CDC로 이벤트 발행을 DB 트랜잭션에 묶음. 컨슈머는 멱등 키로 중복 처리 방지
결과불일치가 0건으로 수렴하고 수동 보정 작업이 사라짐
일 30건+→0건데이터 불일치
ISSUE 2세일 이벤트 시 주문 API 지연
문제타임세일 직후 재고 row에 락 경합이 몰려 p99 응답이 4초까지 증가
시도Redis Lua 스크립트로 재고 선차감 후 비동기 DB 반영, 요청 큐잉으로 DB 쓰기 평탄화
결과피크 TPS 3배 상황에서도 안정적인 응답 유지
p99 4.1s→0.35s주문 API 응답

PROJECT 02

실시간 알림 플랫폼

서비스마다 따로 구현되어 있던 푸시·SMS·이메일 발송을 하나의 플랫폼으로 통합했습니다.

프로젝트 개요

기간2021.09 – 2022.08
팀 구성백엔드 3
역할설계 · 핵심 개발
기여도60%

사용 기술

GogRPCRedis StreamsMySQLFCM/APNsPrometheus

주요 기능 및 담당 역할

  • 채널 공통 발송 API(gRPC) 설계 및 템플릿 엔진 개발
  • 우선순위 큐 기반 발송 스케줄러 — 인증번호 등 긴급 알림 우선 처리
  • 사용자별 수신 설정·야간 발송 제한 등 정책 엔진 구현

문제 해결 경험

ISSUE 1대량 마케팅 발송이 인증번호를 지연시킴
문제단일 큐 구조에서 수백만 건 마케팅 발송이 몰리면 인증 문자가 수 분씩 늦게 도착
시도Redis Streams를 우선순위별로 분리하고 워커 풀을 가중치 기반으로 배분, 외부 벤더 호출에 토큰 버킷 레이트 리미터 적용
결과대량 발송 중에도 긴급 알림 지연 없음
최대 3분→2초 이내인증 알림 도착 시간

PROJECT 03 · OPEN SOURCE

tf-guard

Terraform PR에서 인프라 비용 증가와 보안 설정 누락을 자동으로 찾아 코멘트로 남겨주는 CLI 도구입니다.

프로젝트 개요

기간2024.02 – 현재
팀 구성개인 (메인테이너)
역할설계 · 개발 · 운영
기여도85%

사용 기술

GoHCL ParserGitHub ActionsAWS Pricing APIOPA

주요 기능 및 담당 역할

  • terraform plan 결과를 분석해 월 예상 비용 변화를 PR 코멘트로 표시
  • 공개 S3 버킷, 과도한 IAM 권한 등 보안 룰 40여 개 내장, 커스텀 룰 지원
  • GitHub Action 마켓플레이스 배포, 문서 사이트 운영

문제 해결 경험

ISSUE 1대형 모노레포에서 분석 시간 초과
문제모듈이 수백 개인 저장소에서 분석이 10분을 넘겨 CI 타임아웃 발생
시도변경된 모듈과 의존 그래프만 추적하는 증분 분석 도입, 가격 조회 결과 로컬 캐시와 goroutine 병렬 처리
결과대형 저장소에서도 1분 안에 리뷰 완료
10분+→48초분석 시간
